# Qavor API 学习型接口文档设计

## 目标

在不依赖上游 Yuxi 项目的前提下，为 Qavor 当前实际实现的 HTTP API 编写一份中文学习型文档。读者应能理解接口的业务目的、调用前后关系、字段含义及其在本项目技术栈中的实现位置，并可通过附录快速查找端点。

## 范围

- 以 `internal/api/router.go` 注册的路由和对应 Controller、Service、DTO、Middleware 实现为唯一事实来源。
- 覆盖健康检查、认证、用户、会话/聊天和知识库/RAG 模块。
- 对前端已存在请求封装、但当前 Go 后端未注册或未实现的端点，单独列为“前端预留/后端未实现”，不把它们描述为可调用 API。
- 将已有 `docs/API.md` 的基础速查内容整合进新文档；新文档补充业务解释和调用流程。

## 非目标

- 不修改现有接口、路由、DTO 或业务逻辑。
- 不根据 xerrors/Yuxi 的源码推测 Qavor 的行为。
- 不记录 `.env` 中的敏感配置值。

## 技术背景

后端采用 Go 1.25、Gin 1.11、GORM 1.31 和 PostgreSQL；Redis 用于缓存/基础设施能力，JWT v5 提供身份认证，MinIO 用于对象存储。RAG 能力由 CloudWeGo Eino 及 OpenAI 兼容的模型/Embedding 组件支持。接口文档会把这些技术选择同实际接口行为关联起来，例如 JWT 的身份传递、MinIO 的文件上传、以及知识库文件切分和检索链路。

## 文档结构

新建 `docs/接口说明.md`，按以下顺序组织：

1. 阅读指南与技术栈：说明后端分层和“路由 → Controller → Service → Repository/LLM”的阅读路径。
2. 通用约定：Base URL、鉴权、统一响应、错误码、分页、请求体格式与 SSE（若实现存在）。
3. 模块接口说明：每个端点包含用途、典型调用时机、认证要求、请求字段、成功响应字段、处理流程、常见误解和示例。
4. 端到端流程：登录、知识库建库与文件入库、基于知识库的聊天等实际可达业务路径。
5. 端点速查表：按模块列出方法、路径、鉴权要求、请求类型和一句话用途。
6. 实现状态说明：区分已注册的后端端点和仅在前端出现的预留调用。

## 准确性与验证

- 每条端点均由路由注册反查至 Controller、请求/响应 DTO 和 Service 方法。
- 文档中的字段、HTTP 方法、路径、鉴权要求和响应形状必须与源码一致。
- 对条件注册的知识库与聊天路由，明确其依赖服务成功初始化才会挂载。
- 文档完成后进行链接、标题层级、代码块、端点清单与 `rg` 路由扫描的交叉检查。
