# LLM & Embedding 模型抽象层设计文档（限定 OpenAI 兼容协议）
## 文档信息
- 项目：Agent 对话系统
- 语言：Golang
- 约束条件：**现阶段仅对接 OpenAI 兼容协议**（OpenAI、DeepSeek、硅基流动、Ollama、通义千问兼容模式等全部复用同一套 HTTP `/v1/chat/completions`、`/v1/embeddings` 接口规范）
- 关联模块：会话消息CRUD、SSE流式服务、Agent编排、RAG模块
- 目标：极简架构，避免过度设计；预留扩展接口，后续如需区分厂商无需大规模重构

# 1 概述
系统存在两类模型能力：
1. **对话生成模型（LLM）**：同步对话、SSE流式输出、Function Calling工具调用；
2. **向量嵌入模型（Embedding）**：批量文本向量化，服务RAG相似度检索。

所有模型服务统一遵循 **OpenAI HTTP协议规范**，无需做多厂商多协议兼容。
包划分策略不变：
- `llm/`：对话模型
- `embedding/`：向量嵌入模型

> 优化点：不再设计泛化 `provider` 多路分支（暂时不需要判断不同厂商），**简化 provider 目录结构，但保留抽象接口**。
> 好处：代码精简；接口抽象保留，未来如果出现不兼容协议，只需要新增实现，上层调用代码不动。

# 2 设计原则
1. **适度设计，拒绝过度抽象**：当前仅 OpenAI 协议，移除无用的厂商分支；
2. **职责隔离**：对话包 llm、向量包 embedding 完全独立，不混用结构体、http 客户端；
3. **依赖倒置**：业务层依赖顶层接口，不直接依赖底层http请求代码；
4. **原生支持流式**：适配项目 SSE/WebSocket 对话链路；
5. **无反向依赖**：llm / embedding 包禁止导入 entity、conversation、service、数据库层代码；
6. **协议抹平**：内部统一结构体，隔离原始OpenAI http响应细节。

# 3 整体架构
```
业务层（AgentService / SSE Controller / RAG Service）
        ↓ 调用工厂获取客户端
┌──────────┐            ┌──────────────┐
│   llm/   │            │ embedding/  │
│ 对话模型包 │            │ 向量模型包   │
│ factory  │            │   factory   │
│ 顶层接口 LLM           │ 顶层接口 Embedding
└─────┬────┘            └──────┬───────┘
      ↓                        ↓
llm/openai.go            embedding/openai.go
  OpenAI协议实现          OpenAI协议实现
```
> 简化调整：
> 暂时删除 `provider/` 子目录，直接放置 `openai.go`。
> 未来出现异构协议，再新建 `provider/` 做扩展，改动极小。

# 4 llm 对话模型包设计
## 4.1 目录结构
```
llm/
├── llm.go         // 顶层抽象接口 LLM
├── factory.go     // 客户端工厂，创建OpenAI客户端实例
├── types.go       // 请求、响应、流式Chunk、工具调用结构体
├── errors.go      // 模块自定义错误
└── openai.go      // OpenAI协议接口实现
```

## 4.2 文件职责
### llm.go 顶层接口
```go
package llm

import "context"

// LLM 对话模型统一抽象
type LLM interface {
	// Chat 同步调用，一次性返回完整结果
	Chat(ctx context.Context, req *ChatRequest) (*ChatResponse, error)
	// ChatStream 流式调用，返回只读通道，推送增量分片（对接SSE）
	ChatStream(ctx context.Context, req *ChatRequest) (<-chan *StreamChunk, error)
}
```

### factory.go
现阶段**不需要 provider 分支判断**，只生产 OpenAI 实现。
```go
package llm

// ClientConfig OpenAI兼容客户端配置
type ClientConfig struct {
	APIKey     string
	BaseURL    string
	TimeoutSec int
}

// NewClient 创建LLM客户端（当前仅OpenAI实现）
func NewClient(cfg ClientConfig) LLM {
	return newOpenAIClient(cfg)
}
```

### types.go
定义统一模型结构体，屏蔽原始OpenAI JSON结构
- `ChatRequest`
- `ChatMessage`
- `ChatResponse`
- `StreamChunk` 【核心，SSE流式输出】
- `ToolDefine / ToolCall / ToolCallDelta` 工具调用
- `TokenUsage`

### openai.go
实现 `LLM` 接口：
封装HTTP请求、请求体序列化、普通响应解析、SSE流式解析、异常包装。

### errors.go
定义模块错误：鉴权失败、请求超时、限流、流式中断等。

# 9 强制约束规范
1. ❌ 禁止合并 llm 和 embedding 为一个包，两者语义不同；
2. ❌ 业务代码禁止直接调用 openai.go 内部结构体，统一通过工厂获取接口；
3. ❌ llm/openai.go、embedding/openai.go 两套http客户端相互独立，不要共用；
4. ❌ 不要在 llm/embedding 内部写入会话、消息、数据库相关逻辑；
5. ✅ 所有对外依赖全部通过顶层接口，不要直接暴露http底层。

# 10 和现有系统集成说明
1. **会话/消息CRUD**
   llm 包只接收组装完成的 `[]llm.ChatMessage`；**消息实体转换逻辑放在上层Service**，llm不依赖entity.Message；
2. **SSE流式模块**
   SSE Controller 调用 llm.ChatStream 获取通道，循环转发前端；
3. **Agent模块**
   Agent循环（思考、工具调用）依赖 llm.LLM 接口；
4. **短期记忆模块**
   MemoryService 查询消息列表，组装 llm.ChatMessage，传给LLM。
